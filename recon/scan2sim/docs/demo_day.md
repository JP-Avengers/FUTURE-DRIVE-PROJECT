# 발표 당일 순서 (D)

12/7 발표와 12/5 리허설에서 서버를 켜고 시연하는 순서. `implementation.md` 11장을 명령까지 풀어 쓴 것.
스크립트 설명은 `deploy/README.md`, 명령은 모두 레포 맨 위 폴더에서 실행함.

**11.27에 ThinkPad에서 점검해 고친 판.** 서버를 끄지 않고 볼 수 있는 것(예시 파일 한 건 끝까지 · `status.sh` · QR · 결과 화면 주소 · 서버 인자)과 그 전 이틀 동안 실제로 한 것(터널 · 아이폰 업로드 · 폰 LTE 접속 · 다른 컴퓨터 접속 · 재부팅 뒤 자동 시작)을 반영함. **처음부터 끝까지 순서대로 한 번에 돌려 본 것은 아님** — 12/5 리허설에서 함. "안 될 때" 표의 명령은 읽어서만 맞춰 봄.

## 꼭 알아 둘 것 (11.27 점검에서 나온 것)

1. **값을 빼고 `start.sh`만 부르면 남겨 둔 결과가 지워질 수 있음.** 서버 기본값은 "끝난 지 24시간 넘은 작업 폴더를 지움"이고, 켜질 때도 지움. 그래서 ThinkPad에는 `~/scan2sim_run/settings.env`에 `S2S_TTL_HOURS=0` · `S2S_KEEP=-1`을 적어 둠(`deploy/README.md`). `start.sh`가 켤 때 "작업 보관 …" 줄로 어떤 값인지 보여 주니, "지우지 않음"인지 보고 넘어감.
2. **ThinkPad는 켜면 서버와 터널이 이미 떠 있음**(`autostart.sh`, 부팅 약 35초 뒤). 그래서 당일에는 `start.sh`가 아니라 `status.sh`로 주소와 QR을 봄. `start.sh`를 부르면 "이미 켜져 있음"으로 멈춤.
3. **터널 주소는 켜질 때마다 바뀜.** 접속 코드는 그대로.
4. 자동으로 켜진 서버에는 절전 막기(`systemd-inhibit`)가 안 붙음. 덮개 닫기 무시와 "가만히 둬도 잠들지 않음" 설정으로 버티므로 그 둘을 바꾸지 않음. 걱정되면 당일에 `stop.sh` → `start.sh`로 손으로 다시 켬(주소가 바뀜).
5. ThinkPad는 자동 로그인이라 덮개를 열면 비밀번호 없이 바탕화면이 뜸. 발표 장소에서 자리를 비우지 않음.

## 전날까지

1. ThinkPad를 최신 main으로 올림. 서버가 켜져 있으므로 끄고 올림(터널 주소가 바뀜 → 팀에 다시 알림).

    ```bash
    bash recon/scan2sim/deploy/stop.sh
    git pull --ff-only
    bash recon/scan2sim/deploy/install.sh
    bash recon/scan2sim/deploy/start.sh          # settings.env 를 읽음 — "작업 보관 … 지우지 않음" 확인
    PY=~/scan2sim_env/bin/python bash recon/scan2sim/tests/run.sh     # 끝 줄 TESTS_OK
    ```

2. 예시 파일은 `~/scan2sim_samples`에 둠. 지금 있는 것은 가상 Stray 촬영본 `synth_room_s0.zip`(43 MB) 하나. **사람 얼굴이 찍힌 촬영본은 넣지 않음** — 융복 2층 강의실 촬영본에는 사람이 찍혀 있어 넣지 않고, 미리 끝내 둔 결과 화면으로 보여 줌(5번). 화면에 보일 이름은 `~/scan2sim_samples/samples.json`에 적음(없으면 파일 이름).
   - 화면에는 아직 예시 파일 단추가 없음(A). 서버 쪽은 됨: `POST /api/samples/<이름>/jobs`로 만든 작업이 23초 만에 끝까지 가고 결과 4종이 받아짐(11.27).
3. 덮개를 닫아도 잠들지 않게 돼 있는지 봄(ThinkPad는 돼 있음). 충전기를 챙김.
4. 디스크 여유를 봄(`status.sh`). 11.27에 86 GB. 기준(20 GB)보다 적으면 서버가 새 작업을 받지 않음. 지우지 않게 켜 두었으므로 올린 파일이 쌓임 — 인문대 2층 한 건이 약 0.6 GB.
5. 미리 끝내 둔 결과. 지우지 않게 켜 두었으므로 전날 만들어도 남음. 11.27 밤에 `1b241ad` 판으로 다시 만든 것:

    | 무엇 | 작업 번호 | 판정 | 처리 |
    |---|---|---|---|
    | 가상의 방 | `b43fa9b3da05` | 주의 | 24초 |
    | 융복 2층 강의실 (시연용) | `ca5cb1e43834` | 주의 | 84초 |
    | 인문대 2층 복도 | `0fd7d3b6caf0` | 주의 | 310초 |

    - 엔진이 바뀌면 결과도 바뀌므로, **마지막으로 main을 올린 뒤(1번) 세 건을 다시 만듦**:

    ```bash
    ~/scan2sim_env/bin/python recon/scan2sim/deploy/check.py ~/scan2sim_samples/synth_room_s0.zip
    ~/scan2sim_env/bin/python recon/scan2sim/deploy/check.py ~/02_촬영본_강의실_2분.zip
    ~/scan2sim_env/bin/python recon/scan2sim/deploy/check.py ~/scan2sim_in/인문대학2층_20261125_서진석.zip
    ```

    - 강의실 결과에는 "로봇이 제자리에서 돌 수 있는 넓이가 1.29 m² 뿐임 (5 m² 미만) — 주행 공간이 좁아 주행 실패가 예상됨" 주의가 붙음(11.25 판의 결과에는 없던 문구). 맵이 깨진 것이 아니라 책상이 촘촘한 방이라는 뜻(판정은 맵 상태만, 주행 공간은 따로 한 줄 — C13).
6. 터널이 안 될 때 보여 줄 녹화 영상을 노트북에 넣어 둠.
7. 접속 코드 틀린 횟수 제한을 당일에 켤지 정함. 켜 두면 같은 주소에서 10분 안에 30번 틀렸을 때 그 주소가 5분 막힘. 발표 장소 와이파이를 청중과 같이 쓰면 밖에서 한 주소로 보여 **함께 막힘**(ThinkPad 자체 화면은 따로 셈). 끄려면 `settings.env`에 `S2S_CODE_TRIES=0`을 더하고 다시 켬.

## 당일 — 켜기 (발표 30분 전까지)

1. ThinkPad를 켜고 충전기와 네트워크를 연결함. 발표 장소 네트워크가 안 되면 휴대폰 핫스팟. 켜고 1분쯤 기다림(자동 시작).
2. 상태를 봄. 접속 주소 · 접속 코드 · 링크 · QR이 나옴.

    ```bash
    bash recon/scan2sim/deploy/status.sh
    ```

    - "서버 켜짐 · 응답함", "터널 켜짐"인지 봄. 꺼져 있으면 `bash recon/scan2sim/deploy/start.sh`(값은 `settings.env`에서 읽음).
    - 네트워크를 바꿨으면(핫스팟 등) 터널이 다시 붙으면서 주소가 바뀜 → `status.sh`를 다시 봄.
    - QR 그림은 `~/scan2sim_run/qr.png`(`status.sh`를 부를 때마다 지금 주소로 다시 그림). 발표 화면에 띄울 때 이 파일을 씀. **링크와 QR에는 접속 코드가 들어 있으므로 공개하는 발표 자료 · 저장소에는 넣지 않음.**
    - 화면은 아직 링크의 `?code=`를 읽지 않음(A). QR로 들어와도 코드 칸이 비어 있으니 **접속 코드를 QR 옆에 같이 띄움.**
3. 다른 기기(폰)로 QR에 들어가 접속 코드를 넣고 파일 한 건을 올려 끝까지 돌려 봄: 결과 화면 → 결함 목록을 눌러 3D 화면의 결함 강조 → `bundle.zip` 내려받기. (오른쪽 아래 Nav2 지도 그림에는 결함 표시가 없음.)
   - 그 뒤 `status.sh`의 서버 줄이 "방문자 주소 CF-Connecting-IP 로 구분"인지 봄. "구분 안 됨"이면 틀린 횟수 제한을 끔(전날 7번).
4. 미리 끝내 둔 결과의 화면 주소를 적어 둠: `<터널 주소>/#<작업 번호>`. 그 주소로 들어와도 접속 코드를 먼저 넣어야 결과가 열림.
5. `status.sh`로 한 번 더 봄: 서버 응답 · 터널 주소 · 기다리는 작업 0건 · 디스크 여유.

## 시연 중

- 한 번에 한 건만 처리하고 나머지는 줄을 섬. 기다리는 작업이 5건이면 새 작업을 받지 않고 "몇 분 뒤 다시"를 알려 줌.
- 한 건이 20분을 넘으면 멈추고 실패로 표시함. 그 뒤 작업은 그대로 이어짐.
- 걸리는 시간(ThinkPad, 11.27 밤 `1b241ad` 판): 가상의 방 24초, 강의실 2분 촬영본 84초, 인문대 2층(583 MB) 310초(메모리 +12 GB까지). 그 전 판에서는 각각 21~31초 · 102~158초 · 316~633초였음. 올리기는 학교 와이파이에서 380 MB 약 30초 ~ 583 MB 약 3분.
- 청중이 올린 파일은 이 노트북에 저장됨. **지금 설정으로는 저절로 지워지지 않고, 발표가 끝난 뒤 지움**("끝난 뒤"). 물어보면 그렇게 답함.
- 접속 코드를 여러 번 틀린 사람에게는 "접속 코드를 여러 번 틀림 — N분 뒤에 다시 해 볼 것"이 보임.
- 상태를 볼 때는 `status.sh`, 자세히는 `tail -f ~/scan2sim_run/server.log`.

## 안 될 때

| 증상 | 할 일 |
|---|---|
| 터널 주소가 안 나옴 | `tail -50 ~/scan2sim_run/tunnel.log`. 밖으로 나가는 7844 포트(TCP · UDP)가 막힌 네트워크면 핫스팟으로 바꾸고 `stop.sh` → `start.sh` |
| 주소가 바뀜(터널이 다시 켜짐) | `status.sh`로 새 QR을 띄움. 미리 적어 둔 결과 화면 주소도 앞부분을 새 주소로 바꿈(작업 번호는 그대로) |
| 폰에서 올리기가 느리거나 끊김 | 화면이 받은 자리부터 이어 올림(8번까지). 그래도 안 되면 미리 끝내 둔 결과 화면으로 넘어감 |
| 서버가 응답하지 않음 | 죽으면 2초 뒤 스스로 다시 켜짐. 돌던 작업은 줄에 다시 들어감. 1분 넘게 안 되면 `stop.sh` → `start.sh` |
| 접속 코드가 맞는데 막힘(429) | 같은 네트워크에서 누가 여러 번 틀린 것 — 5분 기다리거나, `settings.env`에 `S2S_CODE_TRIES=0`을 더하고 `stop.sh` → `start.sh` |
| 핫스팟으로도 터널이 안 됨 | `stop.sh` 뒤 `S2S_TUNNEL=0 bash recon/scan2sim/deploy/start.sh`로 켜고 노트북 화면(`http://127.0.0.1:8000`)으로 직접 시연 |
| 그것도 안 됨 | 녹화 영상 |

`stop.sh` → `start.sh`로 다시 켤 때 `settings.env`가 있으면 값을 따로 안 줘도 됨. 없으면 `S2S_TTL_HOURS=0 S2S_KEEP=-1`을 앞에 붙임(안 붙이면 남겨 둔 결과가 지워짐).

## 끝난 뒤

```bash
bash recon/scan2sim/deploy/stop.sh
bash recon/scan2sim/deploy/autostart.sh off      # 안 하면 다음에 켤 때 서버와 터널이 또 떠서 밖에 열림
```

그다음 남길 것을 정하고 지움. **아래 `rm`은 미리 끝내 둔 결과까지 다 지움** — 남길 작업 폴더(`~/scan2sim_jobs/<작업 번호>`)는 먼저 다른 곳으로 옮김.

```bash
rm -r ~/scan2sim_jobs                                    # 청중이 올린 파일과 결과
rm -f ~/scan2sim_run/qr.png ~/scan2sim_run/boot.log      # 접속 코드가 든 그림 · 기록
rm -f ~/scan2sim_run/code                                # 발표에서 보인 코드를 다시 쓰지 않게 (다음에 켜면 새 코드)
```

`~/scan2sim_in/`(시험 촬영본 원본) · `~/scan2sim_samples/` · `~/02_촬영본_강의실_2분.zip`(**사람이 찍힌 촬영본**)은 위 명령으로 지워지지 않음 — 남길지 따로 정해서 지움.

## 아직 정해지지 않았거나 확인 안 된 것

- 화면이 링크의 `?code=`를 읽어 접속 코드를 채우는 것(A) — 11.27 main에는 없음.
- 화면의 예시 파일 단추(A) — 11.27 main에는 없음. 서버 쪽 `GET /api/samples` · `POST /api/samples/<name>/jobs`는 있음.
- 발표 장소 네트워크에서 터널이 붙는지, 올리는 속도(M4 리허설에서 잼).
- 이 순서를 처음부터 끝까지 한 번에 돌려 보는 것(M4 리허설).
- 접속 코드 틀린 횟수 제한을 당일에 켤지.
- 자동 로그인을 껐을 때도 다시 켜진 뒤 알아서 켜지는지(지금은 자동 로그인 상태에서만 확인).
- 발표 뒤 남길 결과가 무엇인지.
