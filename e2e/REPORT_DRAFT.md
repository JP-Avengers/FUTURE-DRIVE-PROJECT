## E.1 개요

### E.1.1 과제와 E 의 역할

본 과제는 교내 실외 주차장 일부 구역(IT대학 1호관 남측, 약 119 m 폐루프)을 촬영해 Visual SLAM · 3D Reconstruction 으로 디지털 트윈을 구축하고, NVIDIA Isaac Sim 에서 ROS 2 기반 카메라 E2E 자율주행(Nav2 미사용)을 시뮬레이션으로 검증하는 것이다 [R1]. 파트는 A(센서) → B(SLAM) → C(메쉬 · USD) → D(Isaac Sim · PM) → E(E2E · 평가) 순으로 이어지며, E 의 모델은 다시 D 의 평가로 돌아온다 [R1].

E 의 역할은 다음 네 가지이다.

1. D 로부터 교사 데이터를 받는다 — 인계 규약 `d2e_teacher.md` [R3].
2. 교사 데이터로 E2E 주행 모델을 학습한다 [R6].
3. 모델 파일과 forward pass 를 D 에 넘긴다 — 인계 규약 `e2d_model.md` [R4].
4. 고정 시나리오 60회 결과를 분석하고 지표를 해석한다(실행은 D) [R13].

### E.1.2 목표

- 전면 카메라 영상 · 현재 속도 · 앞쪽 경로를 입력받아 선속도 v · 각속도 ω 를 내는 E2E 모델을, 실제 주차장 디지털 트윈(맵 v0.4b r3)에서 모은 교사 데이터로 파인튜닝한다.
- 고정 시나리오 60회 폐루프 주행으로 검증하고, 비교군 Nav2 와 사전학습 가중치 그대로의 모델(제로샷)과 비교한다 [R13, R14].
- 회당 판정은 수행계획서 2.4 의 기준 6개 — 완주, 기준선 이탈 2.0 m 이하, 충돌 없음, 10 s 이상 정지 없음, 마지막 경유점 1.0 m 이내, 주행 거리가 경로 길이의 80 % 이상 — 의 AND 이다 [R14 §2.2, R11 Nav2 절].

## E.2 모델 선정

### E.2.1 경과

- **초기 기준선**: 간트상 "E2E 기준선 재현"(09.22–10.05) 작업이 있었으나 [R6], 저장소에는 서버 학습 · 추론 환경(`envs/ml_env`) 점검에서 ResNet18(입력 192×256) 추론 시간을 CPU 5.4 ms · GPU 0.7 ms 로 확인한 기록(10.13)만 있고 [R18], ResNet18 기반 모델을 학습 · 평가한 기록은 없다.
- **X-Mobility 제로샷 주행(D)**: 공개 사전학습 가중치를 그대로 써서 실제 주차장 씬에서 기준 경로 한 바퀴를 완주하였다 — 맵 v0.4b r3(10.12), v0.5(10.14 · 10.15), v0.6(10.30) [R11, C:4af7131, C:39630cb, C:a147038, C:1e9582e]. 수치는 E.6.4 에 정리하였다.
- **확정**: 11.2 팀 회의에서 X-Mobility(NVlabs/X-Mobility)를 E2E 모델로 확정하였고, D 는 교사 데이터를 X-Mobility 학습 형식(xm_v1)으로 변환해 넘겼다 [R3, R6, C:6ec8a57].

### E.2.2 선정 근거

11.2 회의의 선정 사유는 저장소에 문서로 남아 있지 않다. 아래는 저장소와 논문에 기록된 사실 중 선정과 관련된 것을 정리한 것이다. 【회의록 확인 후 기입: 11.2 팀 회의 선정 사유 · 함께 검토한 후보】

1. **입출력이 프로젝트 규약과 일치한다.** X-Mobility 는 전면 RGB 영상 1장, 전진 속도, 로봇 좌표계 경로 20점을 받아 6차원 명령(그중 선속도 · 각속도)과 경로 5점을 낸다 [P Table I, II-E]. 프로젝트 토픽 `/front_camera/image_raw` · `/chassis/odom` · `/route` → `/cmd_vel` 과 대응된다 [R4, R5].
2. **로봇 · 시뮬레이터 · 교사가 같다.** 사전학습 데이터는 Isaac Sim 에서 Nova Carter 로 수집했고 교사는 Nav2 이다 [P III-A]. 본 과제의 로봇도 Nova Carter 이고, 교사 데이터 일부와 비교군도 Nav2 이다 [R5, R11].
3. **사전학습 가중치와 학습 코드가 공개되어 있다.** 가중치는 Hugging Face `nvidia/X-Mobility` 의 `x_mobility-nav2-semantic_action_path.ckpt`(로그인 · 약관 동의 후 받음) [R6, X7], 학습 코드는 Apache 2.0 [X7].
4. **제로샷으로 실제 맵 한 바퀴를 완주한 기록이 있다** (E.6.4).
5. **논문 보고 성능**: 창고 시나리오 성공률 96 %(Nav2 58 %, BC 92 %, MILE 34 %), 무작위 장애물 시나리오 68 %(Nav2 34 %, BC 56 %, MILE 26 %) [P IV-A, Table III]. 논문 환경의 결과이며 본 과제 환경의 결과가 아니다.

### E.2.3 구조

X-Mobility 는 관측 인코더, 상태 추정망(재귀 세계 모델), 상태 예측망, 행동 정책망, 다중 디코더로 구성된다 [P II-B~II-E]. 코드에서는 상태 추정 · 예측이 `RSSM` 모듈 하나로 구현되어 있다 [X2 `rssm.py`]. 상태 추정망은 직전 이력 h, 직전 행동 a, 현재 관측 임베딩 o 로 정규분포 상태 s 를 추정하고(GRU 로 이력 갱신), 잠재 상태 z = [h, s] 를 디코더와 정책이 함께 쓴다 [P II-B, II-C1].

### E.2.4 사전학습 방식 (논문)

- **데이터**: Isaac Sim 창고 4종, 5 Hz 기록. Nav2 교사 100K 프레임 + 무작위 행동 160K 프레임 [P III-A]. 프레임마다 영상 3×320×512, 속도, 의미 라벨 7×320×512, 경로 20×2 · path 5×2(교사 데이터만), 명령 6 [P Table I].
- **2단계 학습**: 1단계 무작위 행동 데이터로 세계 모델 100 에폭, 2단계 교사 데이터로 세계 모델과 정책을 함께 100 에폭(RGB 디퓨저 끔). 8 × H100, 배치 32, 학습 표본 5프레임, AdamW lr 1e-5, OneCycleLR(pct_start 0.2), weight decay 0.01, 16-mixed [P II-F, III-B, Table VIII].
- **코드 기본값과의 차이**: 코드 기본 설정은 `SEQUENCE_LENGTH=4`, GPU 당 `batch_size=4` 이다 [X1]. 논문의 학습 표본 5프레임과 다르다.
- **공개 가중치**: `x_mobility-nav2-semantic_action_path.ckpt` 는 교사 데이터로 의미 분할 · 명령 · 경로 디코딩을 켜고 학습한 것이다 [X7].

- **본 과제와의 관련**: 의미 분할을 끈 변형은 창고 SR 은 96 % 로 같으나 무작위 장애물 SR 이 68 → 36 % 로 떨어졌고, 저자들은 의미 분할 디코딩이 세계 모델의 잠재 상태에 환경 정보를 담게 하는 데 중요하다고 해석하였다 [P IV-B2]. 본 과제는 의미 분할 라벨이 없어 이 디코더를 끄므로(E.4.2) 장애물 시나리오에서의 위험 요인으로 본다.

### E.3.2 학습 형식 변환 (xm_v1)

- **표본**: 카메라 20 Hz 중 헤더 시각 기준 5 Hz, `/teacher/status` 단계가 FOLLOW 인 구간만. 0.3 s 넘게 끊긴 곳마다 run 파일을 나누고 8행 미만 run 은 버림 [R12].
- **열**: `camera_image` 640×480 → 512×320 JPEG(품질 90) · `driving_command` [v, 0, 0, 0, 0, ω] = `/teacher/cmd_vel` · `ego_speed` = `/chassis/odom` 선속도 · `route_poses` 20점 × 2(로봇 좌표계, 현재 위치 + 기준선 앞쪽 0.5 m 간격 19점, 구간 시나리오는 목표 s 에서 끊고 끝점 반복) · `path` 5점 × 2(실제로 지나간 미래 위치 t + k·0.84 s, k = 0..4 — 간격은 공개 샘플에서 추정) + 분석용 열 [R12].
- **위치**: `nav2_v1` 은 정답 위치 `/ground_truth/tf`, `raw_v1` 은 그 토픽이 없어 odom + 씬 시작 자세로 계산. 위치 점검 최대 1.4 cm [R2, R12].
- **의미 분할 열 없음** → 학습 설정에서 `ENABLE_SEMANTIC=False` [R3, R12].
- **split(녹화 묶음 단위)**: 자동 교사 마지막 반시계 묶음(`1013_121103`) → val, 마지막 시계 묶음(`1013_122008`) → test, Nav2 콘 반시계(`1014_123928`) → val, 슬라럼 시계(`1014_115111`) → test, 나머지 train. 같은 시나리오의 반대 방향 녹화는 train 에 남겼다 [R12 `export_xmobility.sh`, R3].

- **전달**: 서버는 D 만 접근하므로 구글 드라이브 zip 으로 받았다 [R3].

### E.3.5 발견 사항과 한계

1. **val · test 가 방향으로 갈렸다.** val 의 경로 지시는 직진 · 좌회전뿐이고 test 는 직진 · 우회전뿐이다(표 E-6) [E1]. 기준선 구조상 시계 방향의 꺾임은 모두 우회전, 반시계 방향은 모두 좌회전인데 [R17], val 두 녹화가 모두 반시계, test 두 녹화가 모두 시계이기 때문이다 [R12]. 그 결과 (a) val_loss 최소로 고르는 체크포인트 [R7] 가 좌회전 구간 성능에 치우쳐 선택될 수 있고, (b) 오프라인 test 지표에는 좌회전 구간이 없다. Nav2 장애물 녹화를 맞바꾸는 안(val ← 슬라럼 시계, test ← 콘 반시계)을 D 에 제안하였고, 원본을 건드리지 않고 맞바꾼 판(xm_v1.1)을 만드는 도구 `e2e/resplit_xm.py --preset v1.1` 을 작성하였다(합성 데이터로 시험) [R20]. 맞바꾸면 val · test 모두 양방향 꺾임이 들어간다(자동 교사 부분은 여전히 한 방향씩). 맞바꾼 판 xm_v1.1 은 준비해 두었고, 지시 분포 {0 : 1 : 2} 는 val 2,603 : 1,759 : 278 · test 2,722 : 261 : 1,738 이다(계산: 표 E-6 행 합). 파인튜닝 1차(`xm_ft_v0.1`)는 맞바꾸기 전 xm_v1 로 학습 · 평가하였다 [E2]. 【D 확인 후 기입: 맞바꿈 확정 여부 · MANIFEST v1.1 행】
2. **run 파일 수가 기록과 다르다.** MANIFEST 는 "끊긴 곳마다 run 파일(110개)" 이라 적었으나 [R2], 받은 zip 의 파일은 66개(train 54 · val 6 · test 6)이다. 행 수는 47,572 로 일치한다 [E1]. 【D 확인 후 기입: 110 과 66 의 차이 원인】
3. **교사 간 속도가 다르다.** 명령 v 평균은 자동 교사 0.57~0.59 m/s, Nav2 교사 0.66~0.70 m/s 이다(표 E-6) [E1]. 모델 입력에는 어느 교사의 장면인지 알려 주는 정보가 없으므로, 모델은 두 교사 행동이 섞인 분포를 학습한다. 폐루프 랩 시간 · 속도를 해석할 때 이 점을 감안한다.
4. **의미 분할 라벨이 없다.** 의미 분할 디코더를 끄고 학습하므로 논문의 "w/o Semantic" 조건에 해당하며, 논문에서는 이 조건의 무작위 장애물 성공률이 크게 낮았다(E.2.5) [P Table III].
5. **데이터 규모와 다양성.** 47,572장으로, 논문 Nav2 교사 데이터 100K 프레임의 약 0.48배(계산)이다 [R2, P III-A]. 맵 한 판(r3) · 기준선 하나 · 장애물 시나리오 8종에서 모은 것이다 [R2].
6. **화면 비율이 바뀐다.** 640×480(4:3) 영상을 512×320(16:10)으로 줄여 저장한다 [R5, R12]. 학습과 추론이 같은 전처리를 쓰므로 둘 사이 불일치는 없으나 [R4], 사전학습 데이터의 카메라 화각 · 비율과의 차이는 확인하지 않았다.
7. **시퀀스로 쓰이지 않는 행**: 112행(95 + 12 + 5), 전체의 약 0.24 %(계산) [E1]. MANIFEST 의 "버린 샘플 0" 은 변환 단계 기준이며 이 112행과는 다른 개념이다.
8. **씬 판 차이.** 교사 데이터는 r3 에서 모았고, 이후 v0.5(바닥 높이 지도) · v0.6(바닥 1 cm 사진 텍스처) · v0.7(테두리 마감)로 시각이 바뀌었다 [R2, C:6f7e125, C:296bd7c]. 60회 평가 씬 판은 미정이다 [R14 §6-6]. 제로샷 모델은 먼 구역 3D(원경)를 켜면 평균 이탈이 0.80 → 1.59 m 로 커져 [C:39630cb] 배경 변화에 민감하였다. 원경은 건물처럼 보이지 않는 잡음이고 X-Mobility 이탈을 키운다는 이유로 10.30 팀 결정에 따라 맵 v0.7 에서 뺐다 [R19].

## E.5 평가 설계

### E.5.1 오프라인(개루프) 평가

개루프 평가는 교사가 실제로 지나간 상태의 입력을 넣고 예측을 교사 값과 비교하는 것이다. 모델 오차가 다음 입력에 쌓이지 않으므로 폐루프 성능을 대신하지 않으며, 모델 비교 · 퇴행 확인 · 약한 구간 찾기에 쓴다. 논문에서도 개루프 지표가 비슷한 방법들 사이에 폐루프 성공률 차이가 컸다 [P IV-A].

- **학습 중 지표(X-Mobility 내장)**: 선속도 MAE(`linear_mae`), 각속도 MAE(`angular_mae`), 경로 MAE(`path_mae`), 선속도 · 각속도 백분율 오차, 손실(명령 · 경로 · KL)과 그 합 `val_loss` [X5, X4]. 백분율 오차는 목표값이 0 에 가까운 ω(직진 구간)에서 커지므로 보조 지표로만 본다.
- **배포 방식 개루프 평가기** `e2e/eval_offline.py`(11.5) [R21]: run 파일 시작마다 이력 · 상태 · 직전 명령을 0 으로 놓고 한 프레임씩 넣어 배포 노드(X-Mobility `x_mobility_navigator`)와 같은 재귀 방식으로 추론한다. 기본은 직전 예측 명령을, `--teacher-forcing` 은 직전 교사 명령을 넣는다(학습 때 조건). v MAE · ω MAE · ω 부호 일치율(|ω 교사| > 0.1 rad/s 프레임) · 경로 ADE · FDE 를 전체 · 시나리오별 · 경로 지시별 · 장애물 근처(1.5 m 미만)로 나눠 낸다. 같은 명령으로 제로샷 가중치도 평가한다. 11.6 xm_v1 test split(파일 6 · 4,753 프레임, 직전 예측 명령 조건)에 제로샷 · `xm_ft_v0.1` 두 ckpt 로 돌렸다(E.6.3) [E2].
- **약한 구간 분석**: 두 평가의 프레임별 출력을 기준선 s 2 m 폭 구간으로 묶어 ω MAE 나쁜 순 · 제로샷 대비 나빠진 구간을 낸다(N ≥ 10 구간만) [E2].
- **대상 split**: test(현재 우회전만), 참고로 val(현재 좌회전만) — E.3.5-1 의 맞바꿈이 확정되면 그 판으로 다시 잰다. val 개루프 평가는 아직 안 함.
- **참고 수치**: 논문 A-MAE 0.0747 · L-MAE 0.0158 · P-MAE 0.1156 [P Table II]은 데이터가 달라 직접 비교하지 않는다.

## E.7 한계 및 향후 과제

### E.7.1 한계

1. **평가 시나리오와 학습 시나리오가 겹친다.** Nav2 교사 데이터는 평가에 쓸 장애물 8종 · 구간 5종 시나리오 그 자체에서 모았고 [R2, R11], 학습 · 평가 모두 같은 r3 계열 맵 · 같은 기준선이다. 따라서 60회 결과는 처음 보는 환경에 대한 일반화가 아니라 이 환경에서의 주행 성능을 보여 준다. val · test 로 뺀 두 녹화도 같은 시나리오의 반대 방향은 train 에 있다 [R12].
2. **val · test 방향 편중** (E.3.5-1) — 체크포인트 선택과 오프라인 지표의 대표성이 떨어진다. `xm_ft_v0.1` 은 xm_v1 으로 학습 · 평가하여 test 에 좌회전 지시가 없고 best 는 좌회전만 있는 val 로 골랐다. 맞바꾼 판 xm_v1.1(val 2,603 : 1,759 : 278 · test 2,722 : 261 : 1,738)은 11.6 학습 `xm_ft_v0.2`(xm_v1_2 = v1.1 + Nav2 ×3)부터 썼다. 두 test 가 Nav2 녹화를 공유하지 않아 처음에는 자동 교사 행만 비교됐고, 11.7 에 v0.1 · aw30 을 v1.1 test 로 다시 평가해 네 모델을 같은 test 로 비교한다(표 E-15b). 다만 v1.1 test 의 Nav2 녹화는 v0.1 · aw30 의 best 선택(v1.0 val)에 쓰여 그 행은 그쪽으로 조금 기운다.
3. **의미 분할 디코더 없음** — 논문에서 장애물 일반화가 크게 떨어진 조건과 같다 (E.2.5).
4. **교사 혼합** — 속도가 다른 두 교사를 구분 정보 없이 섞었다 (E.3.5-3).
5. **공변량 이동** — 교사가 지나간 상태 분포로만 학습한다. 조향 잡음으로 이탈 복구 장면을 넣었으나(0.3 m 초과 이탈 자동 39.1 % · Nav2 35.6 %) [R2], 모델 자신의 오차가 만드는 상태는 포함되지 않는다.
6. **위치 입력 출처 미정** — 경로 입력에 필요한 위치를 평가 때 어디서 얻는지 정해지지 않았다 (E.5.3).
7. **통계적 검정력** — 60회를 방법 · 시나리오 · 방향으로 나누면 칸당 회수가 작아 구간이 넓다 (E.5.2).
8. **시뮬레이터 특성** — 실제 회전이 명령 ω 보다 약 1.3배 빠르다(9.30 측정, 원인 확인 중) [R5]. 라벨은 명령값이라 학습에는 영향이 없으나 명령 추종 · 궤적 비교 때 감안한다. 과제 목표는 시뮬레이션 검증이며 [R1], 실제 로봇에서의 검증은 본 장에 포함하지 않는다.
9. **제로샷 기준선의 불확실성** — 제로샷 기록은 조건당 1회이고 원경 등 시각 조건에 민감하였다 (E.6.4, E.3.5-8).
10. **파인튜닝 결과는 개루프뿐** — 11.8 현재 결과는 오프라인 개루프 지표(E.6.3)뿐이고 폐루프 60회(11.24–30)는 아직이다. 개루프 개선이 폐루프 성공률로 이어지는지는 알 수 없다 [P IV-A].
11. **장애물 평가 표본이 작다** — test 의 Nav2 장애물 데이터는 test 판마다 녹화 하나(v1.0 슬라럼 시계 685행 · v1.1 콘 반시계 653행)이고, 장애물 1.5 m 안은 40 · 20 프레임, 약한 구간은 구간당 통과 1회이다 (E.6.3).
12. **장애물 구간 ω 개선이 작다** — Nav2 장애물 ω MAE 0.196 → 0.177, 장애물 1.5 m 안은 0.139 → 0.172 로 나빠졌다 (E.6.3). v1.1 test 콘 반시계의 1.5 m 안 20프레임(통과 1회)에서도 FT 모델 여섯 개 모두 ω 부호 일치가 7–27 % 로 제로샷 73 % 보다 낮다(표 E-15b, `results/reeval_v1.1_11_7/`). 장애물 시나리오에서 파인튜닝 모델이 제로샷보다 낫다고 말할 근거는 아직 없다.
13. **Nav2 녹화에서 덜 꺾는다 — 원인은 장애물 회피보다 교사 두 명의 코너 방식 차이** — `xm_ft_v0.1` test 프레임별 진단(`e2e/steer_diag.py`, `results/xm_ft_v0.1/steer_diag.md`): 예측 ω ÷ 교사 ω 기울기 자동 교사 0.86 · Nav2 0.38, 교사 |ω|>0.3 순간 평균 |ω| 예측 0.26 · 교사 0.50, 부호 반대 20 %(자동 0 %), 지연 없음. 그런데 Nav2 급회전 프레임의 **93 %(2,395/2,563, 전체 데이터)는 장애물에서 3 m 넘게 떨어진 코너**이고, 같은 자리(2 m 칸 · 방향별)에서 Nav2 교사는 자동 교사보다 2–3배 세게 · 더 들쭉날쭉 꺾는다(예: 반시계 s 46 m 평균 ω +0.32 ± 0.37 vs +0.09 ± 0.12; 초당 부호 바뀜 0.29 vs 0.13, `e2e/teacher_style.py`, `results/teacher_style_xm_v1_1.md`). 모델이 어느 교사인지 모른다면 같은 코너에서 두 교사의 평균을 배운다 — Nav2 대비 '덜 꺾기'의 대부분은 이 평균이고, 자동 교사 기준으로는 잘 따라간다(11.6 가설). **11.7 수정**: Nav2 를 ×3 복제한 `xm_ft_v0.2`(train Nav2 비중 25.8 → 51.1 %)에서도 자동 교사 코너 예측은 Nav2 쪽(더 세게)으로 가지 않았다 — 두 교사가 다르게 꺾는 시계 칸 5곳(s 10 · 12 · 40 · 48 · 88 m)의 자동 교사 test 프레임 504개에서 평균 예측 ÷ 교사 0.89 → 0.81, 공통 자동 교사 기울기 0.86 → 0.85 [E3]. 평균 가설대로면 세져야 하므로 '같은 자리 평균'만으로는 설명되지 않는다. 모델이 속도 · 직전 명령으로 교사를 일부 구분하고(두 교사 속도가 다름, E.3.5-3), Nav2 쪽 덜 꺾기는 Nav2 교사 자신의 들쭉날쭉함(같은 자리 표준편차 최대 0.37 rad/s, 초당 부호 바뀜 0.29)을 회귀가 작게 예측한 몫일 수 있다(미검증). 장애물 3 m 안은 test 98프레임 · 급회전 12개뿐이라 판단하기 어렵다(부호 반대 42 %). 따라서 오프라인 Nav2 ω 오차는 성능 기준으로 부적절하고 폐루프(cte · 충돌 · 도착)가 판정한다. 대응: ① `xm_ft_v0.2`(Nav2 ×3) — 11.7: Nav2 기울기는 두 녹화 모두 올랐지만(0.49 → 0.54 · 0.38 → 0.43) 자동 교사 2 s 이탈이 0.027 → 0.031 m 로 나빠져 탈락. Nav2 이탈은 녹화에 따라 엇갈렸다(0.158 → 0.162 · 0.168 → 0.153 m, 표 E-15b) ② 장애물 근처 프레임을 늘리는 녹화(D 요청, 같은 장애물은 같은 쪽) ③ 배포 목표 스타일을 정해(부드러운 자동 교사 vs Nav2) 코너 라벨을 한쪽으로 맞추는 것을 검토.
