# 11.9 교사 강제 입력 평가 — 모델은 직전 명령으로 교사를 구분한다

- **무엇**: v0.1 · aw30 을 v1.0 test(4,753)에서 `eval_offline.py --teacher-forcing` 으로 다시 평가했다. 직전 명령 입력에 모델 자신의 직전 예측 대신 **직전 교사 명령**을 넣는다. Kaggle `fd-xm-eval-tf` 판 1, ckpt 는 `fd-xm-ckpts`(v0.1 `d86970ce1faf` · aw30 `4fdf249cda0a`), 평가 1회 ≈ 4.5 분.
- **왜**: `../teacher_id_11_7.md` 는 "모델이 같은 자리의 두 교사를 거의 구분 못 함(추종비 r 0.0–0.3)"을 보였지만, 무슨 입력으로 구분하는지는 관측으로 가르지 못했다(속도 · 직전 교사 명령이 겹침). 교사 강제 입력은 그 질문을 직접 시험한다.
- 기본 평가(자기 예측 입력)가 배포 노드와 같은 조건이고, 이 평가는 진단용이다.

## 해석

- 모델은 **직전 명령 입력**으로 두 교사를 구분한다. 교사의 직전 명령을 주면 Nav2 코너에서도 교사만큼 꺾는다(r 0.9).
- 배포처럼 자기 예측이 다시 입력으로 들어가면, 자동 교사 같은 완만한 명령이 이어져 Nav2 의 급한 코너 · 회피에서 덜 꺾는다. **REPORT 한계 13 의 'Nav2 덜 꺾기'는 두 교사 평균이 아니라 직전 명령 되먹임(노출 편향 · copycat)** 이다.
- 학습 때 직전 명령 입력은 늘 깨끗한 교사 명령이다. 변환기가 `/teacher/cmd_vel` 만 저장하고(`sim/export_xmobility.py`), X-Mobility 는 `action[t-1]` 을 입력으로 쓴다(`model/x_mobility/rssm.py:152`). 그래서 모델은 흔들린 직전 명령을 본 적이 없다. 계획한 잡음 녹화 · DAgger 녹화도 입력 쪽은 여전히 교사 명령이라 이 문제를 직접 풀지 않는다.

## v0.3 방향 바꿈

- `../teacher_id_11_7.md` 의 '교사 역할 나누기'보다 **직전 명령 입력 흐리기**가 먼저다. ChauffeurNet(Bansal 2018)의 past-motion dropout 과 같은 방법이다.
- `e2e/finetune.py --prev-action-dropout P --prev-action-noise σ`(11.9 추가, 기본 끔): 학습 때 RSSM 의 직전 명령 입력만 시간 단계마다 확률 P 로 0 으로 하거나 v · ω 에 잡음을 더한다. 정답 · 평가 · 노드는 그대로.
- 첫 run 제안: aw30 설정 + `--prev-action-dropout 0.5`(xm_v1, 10 에폭). 판정은 기본 평가(자기 예측 입력)의 ② Nav2 기울기 · ③ Nav2 이탈이 오르내리는지, 자동 교사 ① ③ 가 안 나빠지는지(규칙 2). 할당량 때문에 집 PC 또는 11.14 이후.
