## ⓪ 결론

1. **모델은 같은 자리의 두 교사를 거의 구분하지 못한다.** Nav2 가 같은 방향으로 더 꺾는 코너(14칸, 자동 1,322 · Nav2 197 프레임)에서 r 기울기 v0.1 0.17 · aw30 0.22 · v0.2 0.27(ZS 0.02) — Nav2 가 더 꺾는 양의 1/5 만 따라감. 잡음 없는 프레임만 보면 v0.1 0.03 · aw30 0.11 · v0.2 0.16 으로 사실상 0.
2. **'평균' 가설은 글자대로는 틀리고, '다수결'로 맞는다.** 자동 교사 프레임의 예측은 Nav2 쪽으로 안 끌림(예측/교사 자동 1.06–1.09, Nav2 0.29–0.31) — 두 교사 프레임에 같은 '자동 교사 코너'를 낸다. 명령 손실이 L1(기록 손실 ÷ MAE = 10.08–10.30, `compare_11_7` ④)이라 구분 못 하는 상태에서는 라벨의 중앙값 = 다수인 자동 교사(train 시계 자동 16,073 : Nav2 4,481 프레임 = 3.6 : 1, ×3 후 1.2 : 1).
3. **×3 은 공유된 출력을 섞인 라벨 쪽으로 옮겼을 뿐이다.** 고정 코너 칸 10 · 40 · 48 에서 v0.1 → v0.2: 자동 프레임 예측/교사 0.93 → 0.82, Nav2 프레임 0.19 → 0.31. 교사가 다른 28칸 중 13칸은 Nav2 가 **반대 부호**(슬라럼 · 떨림, |cte| 0.6–1.1 m)라 Nav2 비중을 올리면 코너 출력이 0 쪽으로 눌린다 — v0.2 의 자동 교사 덜 꺾기(⑤ 0.894 → 0.806)와 이탈 +17 % 의 기제.
4. **어떤 입력이 교사를 알려 주는지는 이 데이터로 못 가른다.** 속도는 거의 완벽한 교사 표지인데(코너 칸에서 자동 0.50 · Nav2 0.71 m/s, corr(속도, Nav2) 0.99) 모델이 안 쓴다(d + 속도 회귀에서 속도 계수 −0.02 · ΔR² 0.000). 직전 교사 ω 는 Nav2 프레임에서 ΔT 와 같은 값이라(회귀 R² 0.52, d 계수를 흡수) 학습 때 입력된 직전 교사 명령이 교사를 알려 줬을 가능성이 크지만, 평가 때는 직전 **예측**이 들어가므로(`eval_offline.py` 머리말, 학습 rssm.py:152-154 는 교사 명령) 같은 채널이 없다 — `--teacher-forcing` 평가 1회로 확정 가능(아래).
5. **v0.3 은 교사 역할 나누기(데이터)가 맞다.** 교사 id 입력 · 시나리오 가중은 같은 지렛대(공유 출력 이동)이거나 동결 전 검증 불가. 자세한 것은 ⑥.

## ⑤ 해석 (5줄)

1. 구분 못 함: Nav2 가 더 꺾는 코너에서 r 기울기 0.17 · 0.22 · 0.27(v0.1 · aw30 · v0.2), 잡음 없으면 0.03 · 0.11 · 0.16, ZS 0.02 — 네 모델이 두 교사 프레임에 거의 같은 ω 를 낸다.
2. 내는 값은 자동 교사 코너다(예측/교사 자동 0.8–1.1, Nav2 0.1–0.4): 같은 자리에서 소수(3.6 : 1)인 Nav2 라벨은 L1 중앙값에서 밀린다. '평균'이 아니라 '다수결'.
3. Nav2 비중을 올리면(×3) 공유된 출력이 섞인 라벨 쪽으로 옮겨 간다 — 코너 칸에서 자동 0.93 → 0.82(덜 꺾음) · Nav2 0.19 → 0.31. 교사가 다른 28칸의 절반(13)은 Nav2 가 반대 부호(콘 회피 · 떨림)라 눌리는 방향이 0 쪽이다. v0.2 자동 교사 이탈 +17 % 의 원인.
4. 무엇으로 구분하는지는 못 가름: 속도는 완벽한 표지(0.50 vs 0.71)인데 안 쓰고(ΔR² 0), 직전 명령은 학습 때(교사 명령)와 평가 때(예측)가 달라 회귀로는 공선. `--teacher-forcing` 평가 1회가 결정한다.
5. 따라서 '모델이 교사를 알아서 가른다'는 가정으로 Nav2 코너 라벨을 더 넣는 길(×3 · 가중)은 자동 교사를 깎는 대가를 치르고, 코너의 Nav2 라벨은 애초에 로봇이 못 따라가는 떨림(초당 부호 바뀜 0.29)이다 → 코너 라벨은 자동 교사만.
