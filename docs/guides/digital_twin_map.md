# 디지털 트윈 3D 맵 만들기 — 파이프라인 · 가이드라인

자율주행 시뮬레이션(Isaac Sim)에서 주행 시험을 할 수 있는 실제 장소의 3D 맵(USD)을 만드는 순서와 기준입니다.
실외 주차장(IT대학 1호관, 맵 v0.2 ~ v0.8)을 만들며 정한 것이고, 실내(복도) · Polycam 데이터가 오면 바로 USD 로 바꿀 수 있게 일반화했습니다.

> 작성: C 이진우 (2026-10-30 초안, 11-08 일반화 · 실내 · Polycam · 유사성 평가 추가). 촬영(1장)·SLAM(2장)은 A · B 의 방식을 정리한 것이라 A · B 확인이 필요합니다.

## 0. 목표와 결과물

| 목표 | 결과물 | 상태 |
| --- | --- | --- |
| 1. 자율주행 시험이 되는 디지털 트윈 3D 맵 | 주차장 USD `parking_v0.8` (바닥 텍스처 + 테두리 마감, 차 · 원경 없음) | D 확인: X-Mobility · Nav2 한 바퀴 완주 (v0.6, 10.30) · v0.8 확인 대기 |
| 2. 맵을 만드는 파이프라인 · 가이드라인 | 이 문서 + `recon/pipeline/run.py` · `recon/configs/templates/` | 실외 · 실내 · Polycam GLB 틀 준비 (3장 · 6장 · 7장), 유사성 평가 방법 (8장) |
| 3. 실제 장소(실내)에 적용 | 복도 촬영 → 같은 순서로 USD → 주행 시험 | 데이터 대기 — 실내 기능은 공개 샘플(Lounge)로 미리 시험 (6장) |

**"주행 시험이 되는 맵"의 조건** — 보기 좋은 것보다 아래가 먼저입니다.

1. **충돌 바닥이 한 겹**이고 턱 · 납작한 조각이 없음 → 물리 엔진(PhysX)이 멈추거나 바퀴가 걸리지 않음
2. **보이는 바닥이 실제 위치에 있음** → 카메라 화면 속 주차선 · 연석이 실제와 같은 자리
3. **주행 중 보이는 구멍이 없음** → 카메라 기반 모델(E2E)이 엉뚱한 곳을 길로 보지 않음
4. **좌표 · 단위 · 크기가 실제와 같음** (m, Z 위) → 실측과 비교 가능
5. **색이 시뮬레이터 조명 규칙에 맞음** (사진값 sRGB → 선형) → 화면이 하얗게 날아가지 않음

## 1. 촬영 (A)

| 항목 | 기준 | 이유 |
| --- | --- | --- |
| 장비 | RealSense D435i (RGB · Depth · IMU), rosbag2 MCAP | [`a2b_rosbag.md`](../interfaces/a2b_rosbag.md) |
| 경로 | **출발점 = 도착점**, 같은 길을 **시계 · 반시계 양방향**으로 여러 회차 | 출발점을 다시 보면 SLAM 이 누적 오차를 바로잡음. 한 방향만 찍으면 반대편 면이 비어 있음 |
| 카메라 높이 | 바닥용 낮은 카메라(본네트 약 1 m, 아래로 10~12°) + 주변용 높은 카메라(지붕 약 1.5 m) | 낮은 카메라 = 바닥 해상도(2 m 앞 약 0.5 cm/화소), 높은 카메라 = 벽 · 먼 곳 |
| 속도 · 움직임 | 천천히, 급회전 없이, 높이 일정 | 흔들리면 SLAM 이 끊기고 사진이 흐림 |
| 시간 · 조명 | 그림자가 짧고 조명이 일정할 때. 사람 · 차가 적을 때 | 촬영 때 그림자 · 햇빛이 바닥 사진에 그대로 남음. 주차된 차 밑 바닥은 찍히지 않음 |
| 실측 | 줄자로 주차칸 · 차로 폭 · 연석 높이 · 카메라 장착 높이 | 크기 검증(5장) · 깊이 보정. 예: 주차칸 250 cm 로 depth 보정 계수 확인 |
| 근접 사진 (선택) | 특이한 바닥 재질(보도블록 · 석축)은 휴대폰으로 수직 · 흐린 날 · 자를 함께 | 일반 아스팔트 · 콘크리트는 공개(CC0) 재질로 충분 |

## 2. SLAM · 형상 (B)

[`slam/README.md`](../../slam/README.md) 순서: 촬영 QC → depth 거리 보정 → RTAB-Map 매핑(회차 이어 붙이기) → 내보내기 → 원본 depth 형상 메쉬(5 cm TSDF).

C 에게 넘기는 것 ([`b2c_map.md`](../interfaces/b2c_map.md)):

| 파일 | 내용 | 없으면 |
| --- | --- | --- |
| `keyframes_<묶음>/rgb · depth · calib` + `trajectory_<묶음>_camera_optical.txt` | 키프레임 사진 · 깊이 · 내부 파라미터 + **카메라 광학 좌표계 → 맵** 자세 | 필수 (색 · 바닥 텍스처 · 잔상 지우기 · 점검 전부 이것으로) |
| 형상 메쉬 (`geometry_clean_5cm.ply`) | 색 없는 원본 depth 메쉬 | 필수 (또는 C 가 `tsdf.py` 로 키프레임에서 직접) |
| 바닥 높이 지도 (`floor_height.npz`) | 10 cm 칸 바닥 높이 | 실외에서 권장 (없으면 C 가 메쉬에서 뽑음) |
| `outer/objects.csv` · `ground_zones.npz` | 주차 차 위치 · 바닥 구역 | 선택 (주차칸 채우기 · 차 지우기에 씀) |

영문 경로로 복사하고 체크섬을 확인합니다 (Open3D 는 한글 경로를 못 읽음).

## 3. 메쉬 → USD (C, `recon/`)

```bash
# 1) 틀을 물려받는 장소 설정을 만듦 — ★ 표시(이름 · 출력 폴더 · 입력 경로)만 바꿈
#    base: templates/outdoor_rtabmap.yaml | indoor_rtabmap.yaml | polycam_glb.yaml   (예: configs/parking.yaml · corridor.yaml · lounge_glb.yaml)
# 2) 한 명령: 입력 점검 → (메쉬 만들기) → USD → 보이는 구멍 → Blender 미리보기 [→ D 패키지]
python recon/pipeline/run.py --config recon/configs/<장소>.yaml [--package v0.1]
#    --from build (메쉬는 그대로 두고 다시) · --only visible · --no-preview · --force (점검 오류 무시)
```

설정은 틀을 물려받고 바뀌는 것만 적습니다 (`base:`, `recon/pipeline/config.py`). 값을 `null` 로 두면 그 단계를 끕니다 (예: `colorize: null`). 입력 점검(`check_input.py`)이 CHANGE_ME · 경로 · 프레임 수 · depth 단위 · 자세 튐 · 메쉬 범위를 먼저 보고, 오류가 있으면 멈춥니다.

### 데이터가 오면 (체크리스트)

1. 받은 폴더를 영문 경로로 복사 (`~/recon_data/<장소>/`), 체크섬 확인
2. 틀 고르기: RTAB-Map 키프레임 + 자세 → 실외 / 실내 틀, GLB 하나 → Polycam 틀
3. 장소 설정 만들기 (★ 만), `python recon/pipeline/check_input.py --config …` → 오류 0 확인 (경고는 읽고 판단)
4. `run.py` 실행 → `run_summary.json` 의 USD 검증 · 보이는 구멍 · `preview/` 그림 확인
5. 실측(줄자) 대조, 검증용 회차가 있으면 유사성 측정 (8장)
6. `--package v0.1` 로 D 패키지 → C 가 열어서 합성 · 텍스처 경로 확인 후 전달 (보내는 건 담당자가 직접)

| 단계 | 하는 일 | 설정 | 왜 |
| --- | --- | --- | --- |
| 정리 · Z-up · 원점 | 작은 조각 삭제, 중력 방향 Z, 주행 경로 아래 바닥 = z 0 | `cleanup` · `orient` | 판마다 바닥 높이가 흔들리지 않게 |
| 잔상 지우기 | 키프레임 광선이 면을 '뚫고' 더 멀리 찍힌 면 = 지나간 사람 · 차 | `transients` | 유령 물체에 걸림 |
| **바닥 한 장** | 스캔의 겹친 바닥 층을 빼고 바닥 높이 지도로 한 장 새로 깖, 그 위로 솟은 것만 물체로 | `single_floor` | 겹친 바닥 = PhysX 멈춤 · 화면 깨짐 (D 10.12) |
| 색 | 키프레임 사진을 메쉬에 투영 (가림 처리, 여러 묶음 우선순위) | `colorize` | |
| **바닥 텍스처** (v0.6) | 바닥에 사진을 1 cm 텍스처로 굽기 · 밝기 맞추기 · 아스팔트 색 통일 · 주차칸 채우기 · 잔무늬 · CC0 요철 | `floor_texture` | 정점 색(5 cm)은 주차선이 뭉개짐 |
| 충돌 | 바닥 10 cm 격자 + 물체 줄인 것, 바닥 근처 납작한 조각 삭제 | `single_floor.collision_*` | 연석이 경사로가 되지 않게, PhysX 멈춤 방지 |
| 테두리 마감 (v0.7) | 바닥 범위를 1 m 다듬은 경계 밖 정리 + 연석 · 인도 띠, 가운데 섬은 주변 아스팔트로 메움 (나무 모델 · 잔디 · 바깥 땅 · 섬 화단은 어색해서 뺌, 11.01 · 11.06) | `edge` | 원경(스캔 밖 depth 3D)은 건물처럼 보이지 않고 잡음이라 뺌 — 켜면 X-Mobility 평균 이탈 0.80 → 1.59 m (10.30 팀 결정, `far_tsdf` 끔) |
| 하늘 | 지붕 키프레임 하늘 화소로 돔 텍스처 | `sky` | |
| 벽 사진 (실내, 11.08) | 큰 수직 평면을 찾아 `Wall<k>` prim + 1 cm 텍스처 (형상은 스캔 그대로) | `walls` | 복도는 화면 절반이 벽 — 표지판 · 게시물 글씨 |
| 반사 · 합의 거르기 (11.08) | 같은 자리를 본 사진 중 혼자 밝은 장(형광등 반사), 중앙값 색과 크게 다른 장(앞을 가린 화분 · 사람)은 뺌 | `floor_texture.specular` · `walls.specular` · `walls.consensus` | |
| USD | `Floor` · `Visual` · `Wall<k>` · `VisualFar` · `Collision`(안 보임) · `Boundary`(경계벽), m · Z-up, 씬 .usda + 메쉬 .usdc | `usd` | 부분마다 끄고 켜서 비교 |

시간 · 자원 (노트북 16 GB, NVIDIA 없음): 주차장 형상 ~7분 + 바닥 텍스처 굽기 20~60분 (메모리 여유에 따라), 실내 샘플(6 × 3.4 m) 전체 6~10분, GLB 1분 안. 같은 설정으로 다시 돌리면 굽기는 건너뜀(`reuse_bake`).

## 6. 실내(복도)에 적용 — 목표 3

틀: `recon/configs/templates/indoor_rtabmap.yaml` (장소 설정 예 `corridor.yaml` — 입력 경로만 채우면 됨). 공개 RGB-D 샘플(Open3D Lounge, 손에 든 카메라 2,999장)로 미리 시험: `lounge_indoor.yaml`.

| 부분 | 주차장 | 실내 틀 | Lounge 시험 (11.08) |
| --- | --- | --- | --- |
| 바닥 | B 바닥 높이 지도로 한 장 | 메쉬에서 뽑은 바닥 한 장 (5 cm) + 1 cm 사진 텍스처, `ground.flat: true` | 칠한 텍셀 90.5% · 화소 크기 중앙 0.62 cm. `flat` 없이는 손에 든 카메라 높이가 바뀌어 의자 좌석이 바닥으로 잡혀 탁자 밑에 혹이 생김 → 바닥 기준을 한 높이로 고정 |
| 반짝이는 바닥 | — | `floor_texture.specular` (중앙값보다 1.25배 밝고 밝기 0.45 넘는 장 뺌) | 텍셀 0.3% 에서 756장 뺌 |
| 벽 | 정점 색 | `walls`: 넓이 1.5 m² 넘는 수직 평면에 1 cm 사진, depth 가 벽 거리와 맞는 화소만, 비스듬히(70° 넘게) 본 사진 제외, 합의 거르기 | 벽 3면 10.7 m², 게시물 글씨가 또렷해짐. **흰 민무늬 벽은 시점마다 조명 반사가 달라 쐐기 얼룩** — 정점 색(수백 장 평균)이 더 매끈함 → 복도 데이터로 비교해 켤지 정함 (끄기: `walls: null`) |
| 천장 · 테두리 | 하늘 돔 · 연석 · 인도 | 하늘 · 테두리 · 배경 벽 끔, 안 보이는 경계벽만 (벽이 경계) | — |
| 보완 단계 | 아스팔트 색 통일 · 차 자리 채우기 · CC0 | 끔 — 장판 · 타일 무늬는 사진 그대로 | — |
| 충돌 | 바닥 · 물체 | 바닥 한 장 + 물체 5만 삼각형 (벽이 가장 중요, 폭 2~3 m) | 충돌 바닥 오차 95% 0.0 cm · 최대 2.5 cm |

**복도 촬영 추가 요령**: 끝까지 갔다가 같은 길로 돌아와 출발점에서 끝냄 · 문 · 표지판 · 소화전처럼 특징 있는 곳을 화면에 · 카메라를 조금 위로 한 회차를 더 (천장 · 벽 위쪽) · 유리문 · 창문 쪽 직사광 피하기 · 폭 몇 곳과 길이 줄자 실측 · **맵에 안 쓰는 검증용 회차 하나** (8장).

**시험 순서**: (1) 실내 샘플로 평면 바닥 + 텍스처 + 반사 거르기 + 벽 (완료) → (2) 복도 촬영 → B 정리 → 3장 체크리스트 → (3) 5장 점검 + 실측 · 유사성 → (4) D 주행 시험 → (5) 막힌 곳 · 고친 곳을 이 문서에 반영.

## 7. Polycam (아이폰 LiDAR) GLB 입력

틀: `recon/configs/templates/polycam_glb.yaml` → `glb_to_usd.py` (`run.py` 가 `input.format: glb` 이면 자동). 키프레임 · 자세가 없으므로 색 투영 · 바닥/벽 사진 굽기 · 잔상 지우기는 없고, **Polycam 텍스처를 그대로** 씁니다.

| 단계 | 하는 일 |
| --- | --- |
| 불러오기 | 노드 변환 적용, glTF Y-up → Z-up, 단위 m (`input.scale`), 부분(primitive)마다 UV · 텍스처 유지 |
| 수평 · 원점 | 위를 향한 면 중 가장 넓은 낮은 층 = 바닥 → 평면 맞춤으로 기울기 보정, 바닥 z 0, 원점 `min_corner` |
| 보이는 부분 | `Visual<k>` (사진 텍스처 · 정점 색 그대로, 양면) + `FloorFill` (스캔 바닥 2 cm 아래 받침 — 가장자리 · 벽 밑 틈이 비치지 않게) |
| 충돌 | 정리 · 8만 삼각형으로 줄인 메쉬, 스캔 바닥은 빼고 평평한 바닥 한 장 + 경계벽 |
| 가상 경로 | 촬영 경로가 없어 장애물에서 0.3 m 떨어진 빈 바닥의 뼈대 → `drive_path.json` (보이는 구멍 · 미리보기 카메라 자리) |

시험 (11.08): Lounge 결과를 GLB 로 내보내 2° 기울이고 원점을 옮긴 파일 → 기울기 1.97° 로 되찾음, 원본과 형상 차이 중앙 1.2 cm, 같은 자리 렌더에서 텍스처 위치 · 방향 일치 (24초). **실제 Polycam 파일로는 아직 안 해 봄** — 받으면 `check_input` 의 위 축 · 범위 · 텍스처 줄부터 확인.

Polycam 촬영 · 내보내기 요령 (A 확인 필요): LiDAR 모드, 천천히 한 바퀴 + 출발점으로, 바닥이 빠지지 않게 아래도 비춤 · 내보내기 GLB (텍스처 포함, 단위 m) · 가능하면 'Raw data'(사진 · 자세)도 같이 받아 둠 → 나중에 키프레임 방식(1 cm 바닥 텍스처 · 유사성 측정)으로도 만들 수 있음 · 같은 자리를 RealSense 와 동시에 찍으면 두 방식을 비교할 수 있음.

## 8. 유사성 평가 — 실제와 얼마나 같은가

멘토 의견(11.06): 정성 비교부터, 정량 방법은 조사해서 보고. 평가 기준은 결국 "시뮬레이션에서 얻은 결과가 실제에 그대로 통하는가".

| 층 | 방법 | 무엇을 봄 | 주차장 시범 (11.07) |
| --- | --- | --- | --- |
| 형상 | 실측(줄자) 대조 · 키프레임 depth ↔ 메쉬 depth | 크기 · 위치 | 주차칸 폭 2.47 vs 2.50 m (−1.2%, 18칸) · 바닥 depth 차 중앙 2.6 cm |
| 화면 | 같은 자세의 실제 사진 ↔ 렌더, 구역(바닥 · 주변)별, 차 자리 가림 | 카메라가 보는 모습 | LPIPS 바닥 0.35 (v0.6 = v0.8) · 주변 0.62 → 0.78 (원경 뺀 대가) |
| 모델 | 같은 쌍을 X-Mobility 에 넣어 출력 비교 · 같은 경로 주행 결과(이탈 · 완주) sim vs real 상관 | 모델이 같게 반응하나 | E · D 와 협의 |

- 지표: **LPIPS 를 주로** (렌더–실제 차이를 가장 잘 나타냄), PSNR · SSIM 은 참고 — SSIM 은 빈 하늘 · 매끈한 면에 유리해 주변 비교에 쓰면 안 됨 (v0.8 에서 주변이 더 달라졌는데 SSIM 은 올라감). FID · KID 는 수천 장이 필요해 쓰지 않음
- **검증용 회차**: 시범 측정은 맵을 만든 바로 그 키프레임이라 독립 검증이 아님. 촬영 때 같은 길을 한 번 더 찍고 **맵 제작에서 빼 두기** — 그 사진들로 재야 진짜 유사성
- 조명: Blender 렌더는 균일 조명이라 조명 차이가 섞임. 최종 수치는 D 에게 같은 자세 목록을 주고 Isaac Sim 에서 찍어 받음
- 실제 사진에는 번호판 · 사람이 찍혀 있음 — 밖으로 보낼 때는 흐린 비교 그림만
- 스크립트: 지금은 C 작업 폴더(`out/similarity/`), 복도 데이터에 쓰기 전에 `recon/eval/` 로 옮길 예정

## 9. 알려진 한계

- 촬영 범위 밖은 연석 · 인도로 마감하고 그 너머는 하늘 (실제 건물 · 나무 · 바깥 땅은 없음 — 10.30 · 11.01 · 11.06 결정)
- 스캔된 주차 차는 v0.8 에서 지움 (차가 찌그러져 보이고 촬영 날마다 달라서). 라이다가 볼 물체가 줄어 AMCL 확인 필요 — 안 되면 같은 자리에 상자 · 차 모델
- 촬영 때 30 cm 보다 좁은 그림자 · 햇빛 줄은 바닥 텍스처에 남음
- 사진이 안 닿은 바닥 가장자리는 정점 색이라 계단 모양 경계가 일부 남음
- 여러 층 바닥(경사로 · 2층)은 아직 안 됨 (바닥 한 장 = 위치마다 높이 하나)
- 실내 벽 사진: 흰 민무늬 벽은 쐐기 얼룩, 벽에 붙은 화분 잎은 벽 무늬로 남음 (6장)
- Polycam GLB: 키프레임이 없어 지나간 사람 · 잔상을 못 지움, 텍스처 해상도는 Polycam 이 정한 대로 (1 cm 굽기 없음), 가상 경로는 실제 주행 경로가 아님
- 바닥 텍스처 6500×5125 는 [`c2d_usd.md`](../interfaces/c2d_usd.md) 초안의 '2K–4K' 보다 큼 (D 확인: RTF 같음). 줄이려면 `floor_texture.cell_m` 0.016
