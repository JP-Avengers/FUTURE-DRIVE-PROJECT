## 새 데이터를 맞춘 방법

1. 묶음별로 따로 맵을 만들었습니다(10/9 시계 3회차, 10/9 반시계 3회차, 10/10은 회차별). 새 회차를 v0.3 맵에 바로 이어 붙이면 v0.3 부분이 휘었기 때문입니다.
2. **강체 정합**: 바닥 주차선(흰 페인트)으로 수평(yaw + 이동)을, 바닥 평면으로 높이·기울기를 v0.3에 맞췄습니다.
3. **비강체 정합**: 키프레임 자세를 조금씩 휘어, 각 키프레임 주변의 v0.3 바닥 높이와 주차선에 맞췄습니다(v0.3 반시계 때와 같은 방법). 기준 주차선은 v0.3에서 지붕 카메라가 멀리서 보아 부채꼴로 번진 부분을 빼고 촘촘한 선만 썼습니다.
4. **10/10 맞는 구간 고르기**: 키프레임마다 주변 8m의 주차선이 v0.3·10/9 주차선과 맞는지 보고(중앙 15cm 미만), 맞는 구간만 썼습니다.
5. **형상 메시**: 새 원본 depth 메시에서 기존 표면과 15cm 넘게 떨어진 삼각형만 붙이고, 붙인 조각마다 둘레의 기존 바닥 높이에 맞춰 위아래로 옮겼습니다. 순서는 10/9 시계 → 10/9 반시계 → 10/10 R11 → R14 → R12 → R7 바닥 조각입니다.
6. **R7 바닥 조각**: 걸어서 든 카메라가 4~9m 떨어진 바닥을 비스듬히 본 것이라 높이가 들쭉날쭉했습니다. 그래서 **바닥이 있는 범위만 R7에서 가져오고, 높이는 주변 바닥 평면으로 보간**했습니다.
7. **점군**: 기존 점과 10cm 안에 없는 새 점만 더했습니다(10/10은 맞는 구간만).

## TSDF로 쓸 때

```bash
pip install "open3d==0.19.0" numpy
python example_tsdf.py 0.05 10                 # v0.3 시계 437장
```

## 스케일과 depth 보정

- 모든 촬영에서 원본 depth를 Z' = Z / (1 + 0.007·Z)로 보정했습니다(5m에서 0.966배, 10m에서 0.935배). 10/9·10/10은 정렬 depth에도 같은 식을 적용했습니다. **키프레임 depth는 이미 보정된 값이니 다시 보정하지 마세요.**
- 10/10 벽 거리 녹화(3~10m)로 "멀수록 길게 나온다"는 방향을 다시 확인했습니다. 벽 녹화만으로는 계수가 0.004~0.007 사이로만 좁혀져, 주차칸 폭이 실측과 맞는 0.007을 그대로 썼습니다.

## 품질과 알려진 한계

- **C가 요청한 가공 항목(바닥 높이 4.4cm 차이(키프레임 361~452), 색 투영 어긋남, 반시계 이음새 단차)은 v0.4에서 다루지 않았습니다.** v0.3 데이터를 그대로 두었기 때문입니다. 다음 판(v0.5)에서 처리합니다.
- 10/10 회차의 삼각형 아래쪽 변 구간은 쓰지 않았습니다(위 "추가 촬영과 쓴 범위"). 그 근처의 루프 안쪽 구멍(1번)이 남은 이유입니다.
- 반시계 키프레임은 줄A에서 줄 방향으로 최대 0.4~0.8m 어긋날 수 있습니다.
- v0.3 구멍 3번 자리의 바닥 높이는 측정값이 아니라 주변 바닥 평면으로 보간한 값입니다.
