# 주차장 맵 v0.4b — 본네트 기준판 (B → C)

작성 2026-10-11 · RTAB-Map 0.23.7 / ROS 2 Jazzy · 10/9·10/10 본네트 카메라 + 10/5 지붕 카메라

**본네트 카메라로 찍은 10/9·10/10 시계 방향 4회차 맵을 기준으로 바닥 형상을 새로 만든 판**입니다. 좌표계(원점·축·단위)는 v0.3과 같지만, 바닥 높이와 위치는 v0.3과 조금씩 다릅니다. v0.3을 그대로 두고 빈 곳만 채운 판은 v0.4a입니다. 두 판의 차이와 고르는 기준은 `V04_A_B_비교.md`에 있습니다.

## 왜 본네트 데이터를 기준으로 했나

| 확인 | 지붕 카메라(v0.3, 10/5) | 본네트 카메라(10/9·10/10) |
|---|---|---|
| 바닥을 보는 거리 | 약 5~8m (카메라가 위로 5°) | 약 1.5~5m (아래로 약 10~12°) |
| 카메라 바로 아래 바닥 높이의 흔들림 (10~90% 폭) | 25~27cm | **4~5cm** |
| 회차(세션) 사이 바닥 높이 차 | 최대 5cm | 0.2~1.3cm |
| 주차칸 폭 (줄마다 잰 칸 간격, 실측 2.50m) | 줄마다 2.45~2.60m | 시계 맵 2.45~2.50m |

- 따로 찍은 두 본네트 맵(시계, 반시계)이 v0.3 바닥과 다른 곳과 방향이 서로 같았습니다(상관 +0.68). 그래서 **v0.3 바닥에 구역별로 ±15~20cm 출렁임이 있다**고 판단했습니다.
- 반시계로 달린 본네트 맵은 일부 주차 줄에서 칸 간격이 6~8% 짧게 나와, 기준은 시계 맵으로 정했습니다.

## 만든 방법

1. **기준**: 10/9 시계 3회차(R1·R3·R5)와 10/10 R11을 하나의 맵으로 이어 붙이고(회차 사이 연결 210개 이상), 통째로 v0.3 좌표에 옮겨 놓았습니다(강체 1회, 주차선 + 바닥 평면).
2. **반시계 본네트**: 10/9 R2·R4·R6과 10/10 R12·R14를 하나의 맵으로 이어 붙인 뒤, 기준 맵의 주차선과 바닥에 맞춰 키프레임 자세를 조금씩 휘었습니다(비강체). 기준 대비 주차선 차이 중앙 2.5cm, 바닥 높이 차 3.5cm입니다.
3. **지붕(v0.3의 10/5 데이터)**: 시계·반시계 맵을 같은 방식으로 기준에 맞춰 휘었습니다. 기준 대비 주차선 차이 중앙 6.8cm(시계)·10.9cm(반시계), 바닥 높이 차 약 6cm입니다. 지붕 카메라 주차선은 멀리서 봐서 번져 있어 이 값이 원래 큽니다.
4. **형상 메시**:
   - 기준 메시를 깐 다음, 반시계 본네트 메시 → 회차별 본네트 메시 9개 → 지붕 시계 → 지붕 반시계 순으로 **빈 곳만** 채웠습니다.
   - 바닥이 이미 있는 자리에는 높이가 조금 달라도 바닥을 한 겹 더 붙이지 않았습니다.
   - 붙인 조각의 높이는 경계에서 기준 바닥에 맞추고, 경계에서 멀어질수록 보정을 줄였습니다(이음새 단차 완화).
5. **10/9 걸어서 찍은 R7**: v0.3 구멍 3번 자리의 바닥을 채웠습니다. 바닥이 있는 범위만 R7에서 가져오고, **높이는 주변 바닥 평면으로 보간**했습니다.
6. **점군**: 기준 점군에 다른 데이터 중 10cm 안에 기존 점이 없는 것만 더하고 3cm 복셀로 솎았습니다.

## 좌표계와 단위

- 원점·축·단위는 v0.3과 같습니다(미터, z축이 위, x·y 방위는 임의, 맵 위쪽이 북쪽이 아님).
- 기준 맵을 v0.3 좌표에 강체로 한 번 옮긴 것이라, 전체 위치는 v0.3과 맞고 국소적으로 수평 보통 7~20cm, 바닥 높이 ±15~20cm 다릅니다.
- 본네트 궤적은 카메라가 낮아서 지붕 궤적보다 약 0.5~0.6m 아래에 있습니다.

## 색 입히기 (키프레임 RGB 투영)

- 형상은 `geometry_rawdepth_tsdf_5cm.ply`, 색은 키프레임 RGB 투영을 권합니다.
- **우선순위: 본네트 시계 → 본네트 반시계 → 지붕 시계 → 지붕 반시계.** 본네트 키프레임이 바닥을 가깝게 찍어 선명하고, 이 판의 메시와 높이가 가장 잘 맞습니다(키프레임 바닥 − 메시 바닥 중앙 +3.0cm).
- 지붕 키프레임은 본네트가 못 본 곳(서쪽 원형 구역, 바깥 가장자리)에만 쓰는 것을 권합니다. 기준에 맞춘 정확도가 본네트보다 낮습니다.
- **줄A(맵 x 0~5, y −13~10의 세로 주차 줄)는 시계 키프레임을 쓰세요.** 반시계 맵은 이 줄의 칸 간격이 짧게 나옵니다.
- 두 날 모두 17시대 촬영이라 해가 낮았습니다.

## TSDF로 쓸 때

```bash
pip install "open3d==0.19.0" numpy
python example_tsdf.py 0.05 10                    # 본네트 시계(기준) 508장
python example_tsdf.py 0.05 10 --bonnet           # + 본네트 반시계
python example_tsdf.py 0.05 10 --only roof_cw     # 지붕 시계만
python example_tsdf.py 0.05 10 --all              # 전부
```

- 이 폴더에서 네 묶음을 하나씩 실행해 확인했습니다(10cm 복셀, 점군과 거리 중앙 3.9~5.7cm).
- **여러 묶음을 한 TSDF에 섞으면 바닥이 서로 지워질 수 있습니다.** 촬영 날마다 주차된 차가 달라서입니다. 형상은 `geometry_rawdepth_tsdf_5cm.ply`를 쓰고 TSDF는 색·확인용으로 써 주세요.
- Open3D 0.20.0은 쓰지 마세요(`ScalableTSDFVolume`이 빈 메시를 냄).

## 바닥 구멍

v0.3과 같은 방법(v0.3 시계 경로 기준 띠, 10cm 격자)으로 셌습니다.

| 영역 | v0.3 | v0.4b |
|---|---|---|
| 차로 (경로에서 0~3m) | 3.5%, 1㎡ 이상 3곳 | **1.6%, 0곳** |
| 주변 (경로에서 3~6m) | 15.9%, 1㎡ 이상 10곳 | **11.2%, 7곳** (최대 22.2㎡) |

v0.3 `floor_holes.csv`의 13곳이 채워진 비율: 1번 47%, 2번 55%, **3번 81%**(R7, 높이 보간), 4번 98%, 5번 100%, 6번 96%, 7번 85%, 8번 0%, 9번 99%, 10번 97%, 11번 100%, 12번 73%, **13번 99%**.

- 남은 큰 구멍은 삼각형 섬 북서쪽 가장자리(22㎡)와 남서쪽 바깥(12.5㎡)입니다. 주차된 차 자리로 보입니다. 국소 평면으로 메워 주세요.
- 이 구멍 비율은 기준 경로를 어디에 두느냐에 따라 달라집니다. 본네트 경로 기준으로 세면 차로 빈칸은 1.1%입니다.

## 스케일과 depth 보정

- 모든 데이터에 원본 depth 보정 Z' = Z / (1 + 0.007·Z)를 적용했습니다(5m에서 0.966배, 10m에서 0.935배). 본네트 데이터는 정렬 depth에도 같은 식을 적용했습니다. **키프레임 depth는 이미 보정된 값입니다.**
- 10/10 벽 거리 녹화(3~10m)로 "멀수록 길게 나온다"는 방향을 다시 확인했고, 주차칸 폭이 실측과 맞는 0.007을 썼습니다.

## 품질과 알려진 한계

- **이음새 단차**: 0.5m 칸별 중앙 5.2cm, 5cm 넘는 칸 51%입니다(v0.3은 6.5cm·59%). 주로 본네트 바닥과 지붕 바닥이 만나는 차로 바깥 가장자리입니다.
- **C 지적 2(색 투영 어긋남)는 아직 직접 재지 않았습니다.** 다음 판에서 확인합니다.
- 반시계 키프레임은 줄A에서 줄 방향으로 최대 0.4~0.8m 어긋날 수 있습니다.
- 지붕 키프레임은 기준에 덜 맞습니다(주차선 차이 중앙 7~11cm, 남서쪽 구역은 더 큼).
- 건물은 거의 없습니다(카메라에서 20~50m, depth 범위 밖). 박스와 사진 텍스처로 만들어 주세요.
- 주차된 차가 날짜별로 섞여 들어 있습니다.
- 바닥 재질 사진(아스팔트, 연석, 붉은 벽돌 보도, 석축)과 주차칸 사진은 아직 없습니다.
