# B 작업 메모 — 환경 함정과 배운 것

맵 작업(10/5~10/11) 중 시간을 많이 쓴 문제와 결론입니다. 데이터 문제처럼 보이지만 실제로는 환경 문제였던 경우가 많았습니다.

## WSL2 + ROS 2 Jazzy

- **큰 이미지가 DDS에서 대부분 사라짐.** 0.6~0.9MB 이미지가 약 90% 유실되고 `camera_info`만 정상이었습니다. UDP 버퍼, SHM, QoS 설정으로는 해결되지 않았습니다. 재생·depth 정렬·오도메트리·RTAB-Map을 컨테이너 하나에 intra-process로 묶어 해결했습니다(`scripts/rtabmap_intra.launch.py`, `scripts/run_rtabmap.sh`).
- **같은 PC 안의 노드끼리 서로 못 찾음.**
  - mirrored 네트워크(tailscale 포함)에서는 `ROS_AUTOMATIC_DISCOVERY_RANGE=LOCALHOST`에 `ROS_STATIC_PEERS=127.0.0.1`까지 넣어야 했습니다. LOCALHOST만 넣으면 몇 시간 뒤 다시 실패합니다.
  - 새 노트북에서는 mirrored 모드에서 C++ 노드와 Python 노드가 서로를 찾지 못해 NAT 모드로 바꿨습니다.
- **매핑 두 개를 동시에 돌리면 서로 섞임.** 같은 ROS 도메인이기 때문입니다. `run_rtabmap.sh`는 실행마다 `ROS_DOMAIN_ID`를 무작위로 정합니다.
- **스크립트 안의 백그라운드 작업이 SIGINT를 무시함.** 비대화형 셸에서는 `bag play`나 launch가 끝나지 않습니다. `set -m`으로 해결했습니다.
- **긴 작업이 메모리 부족으로 강제 종료됨.** bag을 읽으면 WSL 페이지 캐시가 약 10GB까지 차고, Windows는 이를 사용 중인 메모리로 봅니다. 긴 작업 중에는 `sudo sh -c 'echo 1 > /proc/sys/vm/drop_caches'`를 주기적으로 돌리거나 `.wslconfig`에 `[experimental] autoMemoryReclaim=gradual`을 넣으세요.
- rosbag2 QoS override YAML에는 모든 키(deadline, lifespan, liveliness 등)가 있어야 합니다. `read_ahead_queue_size`는 2000이면 메모리가 부족해서 200으로 씁니다.
- 매핑 결과가 이상하면 데이터를 의심하기 전에 단계별 프레임 수신 수부터 보세요(`scripts/topic_counter.py`).

## 라이브러리

- **Open3D 0.20.0**: `ScalableTSDFVolume`과 tensor `VoxelBlockGrid`가 합성 평면에서도 빈 메시를 냅니다. TSDF는 0.19.0(`~/tsdf_env`)으로 만듭니다.
- **OpenCV `findFundamentalMat(FM_RANSAC)`**: 마스크가 0/1이 아닌 쓰레기 값이라 인라이어 수를 믿을 수 없습니다(4.6, 5.0 모두). `USAC_MAGSAC`은 정상입니다. 맵 사이 매칭 검증은 depth PnP와 중력 기울기 검사로 합니다(`scripts/xmap_match2.py`).
- `~/tsdf_env`의 opencv에는 `HOGDescriptor`가 없어서 `scripts/person_check.py`는 시스템 `python3`으로 실행합니다.

## 매핑·정합에서 알게 된 것

- **D435i depth가 멀수록 길게 나옵니다.** 보정식은 Z' = Z / (1 + 0.007·Z)입니다(5m에서 0.966배, 10m에서 0.935배).
  - 보정한 bag으로 다시 매핑하면 주차칸 폭이 249.4~249.7cm로, 실측 250cm와 맞습니다.
  - 10/10 벽 거리 녹화(3~10m)에서 방향을 다시 확인했습니다. 벽 맞춤만으로는 계수가 0.004~0.007 범위까지만 좁혀집니다.
- **multi-session(`INIT_DB`)은 같은 방향 회차끼리만 이어집니다.** 시계와 반시계 사이에는 회차 간 링크가 0개입니다.
- **지붕 카메라 맵에 본네트 회차를 이어 붙이면 기존 맵이 휩니다.** 회차를 더할수록 커져서 1회차 3cm, 3회차 18cm, 8회차 41cm(중앙)였습니다. 본네트 회차는 본네트 회차끼리 잇습니다.
- **한 번만 돈 맵은 넓은 출구 쪽에서 휠 수 있습니다.** 10/10 단독 맵은 약 3.5m 휘었고, 같은 방향 10/9 맵에 이어 붙이자 사라졌습니다(남은 차이 0.3~1.1cm). 추가 촬영은 기존 맵에 이어 붙이는 것을 기본으로 합니다.
- **반시계 맵은 일부 주차 줄(줄A)에서 칸 간격이 6~8% 짧게 나옵니다.** 다른 날 세 번 모두 그랬고, 원인은 조사 중입니다. 시계 맵은 실측과 맞아 기준은 시계로 잡습니다.
- **본네트 카메라 바닥이 훨씬 고릅니다.** 카메라 바로 아래 바닥 높이의 흔들림(10~90% 폭)이 지붕 카메라 25~27cm, 본네트 카메라 4~5cm입니다. 지붕 카메라 맵(v0.3) 바닥에는 구역별로 ±15~20cm 출렁임이 있었습니다.
- **여러 날 회차를 TSDF 하나로 합치면 바닥이 지워지는 곳이 있습니다.** 날마다 주차된 차가 달라 서로의 관측을 지우기 때문입니다. 회차별 TSDF로 빈 곳을 채웁니다.
- **바닥 구멍 비율은 기준 경로에 따라 달라집니다.** 판끼리 비교할 때는 같은 경로(v0.3 시계 경로)를 씁니다.
- **맵 위쪽은 북쪽이 아닙니다.** 방향은 건물로 정합니다. IT1호관이 북쪽, 실험동물자원관리원이 동쪽입니다.
